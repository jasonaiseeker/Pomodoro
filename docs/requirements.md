# Windows 悬浮番茄钟需求草案

> v0.1历史基线；当前UI增量与46项AC见[产品v0.2](product/requirements-v0.2.md)和[验收主表](acceptance.md)。未变更计时/数据行为继续作为候选输入，批准范围以[项目状态](project-state.md)为准。

- 状态：草案，待需求评审
- 来源：GitHub Issue [#1](https://github.com/troywjz/Pomodoro/issues/1)
- 产品目标：面向 Windows 桌面与 Hyper-V 工作场景的轻量悬浮番茄钟，支持可靠计时、系统托盘与离线本地数据。
- 决策状态：本文中的计时规则、资源预算及实现边界均为提案；依赖、版本、许可、存储后端与系统集成方案仍待架构审批。
- 阶段门槛：Notion 需求文档与 Figma 原型获得用户明确确认前，不启动业务代码、Cargo 项目、功能实现或实现型试验。PR 合并和正式发布也须用户审批。

## 1. 目标与原则

1. 在 Windows 桌面提供清晰、可快速操作的专注计时窗口。
2. 使用 Rust + Slint 作为目标技术方向，保持计时内核、界面、Windows 适配和持久化职责清晰；具体依赖与版本待官方资料核验及架构审批。
3. 计时以单调活动时间差为核心；墙钟只用于记录、改时检测与恢复提示，当前倒计时独立于系统日期和时间调整。
4. 默认离线运行与本地保存；用户能查看、导出和清除数据，数据操作有明确反馈。
5. 对资源预算提出可复现的目标，所有数字在指定发布构建和参考机器上实测后才可作为结果发布。

## 2. 用户与主要场景

- 专注工作者：启动专注段、暂停或结束当前段，观察剩余时间与阶段状态。
- Hyper-V 宿主机用户：在宿主 Windows 桌面上让计时器保持普通置顶，并在管理虚拟机时可见。
- 本地数据用户：查看历史统计，导出 JSON/CSV，或清除本地记录。
- 多显示器用户：移动悬浮窗、更改显示缩放、断开显示器后仍可找回窗口。

## 3. MVP 范围

### 3.1 纳入 MVP

- 专注、短休息、长休息三类阶段；提案默认时长为专注25分钟、短休5分钟、长休15分钟，每4轮长休。配置范围提案：专注1–180、短休1–60、长休1–120分钟，长休间隔1–12轮；只接受整数，字段错误禁用保存并保留旧值，修改只影响下一新段。
- 计时状态：`idle`（空闲）、`running`（运行）、`paused`（暂停）、`completed`（阶段完成）、`recovery`（等待恢复处理）。计时阶段：`focus`、`break`；休息细分为短休与长休。
- 阶段完成后停留在完成状态，等待用户主动选择开始下一阶段、重开本阶段或结束会话；MVP 自动开始关闭且暂不提供开启入口。
- 系统托盘入口、关闭窗口处理、明确退出操作及托盘初始化失败时的可用窗口行为。
- 对休眠/唤醒、锁屏、系统时间调整、异常终止的恢复策略和状态提示。
- 离线本地数据、版本化 JSON 导出、CSV 统计导出、清空数据二次确认，以及清空前备份。
- 多显示器、DPI、键盘操作、焦点行为、可访问性和窗口可见性验收。
- 基本计时历史及每日/周期统计；统计口径在实现前定义并记录。

### 3.2 暂不纳入 MVP（后续候选）

- 云同步、账号体系、跨设备同步、在线分析、社交或团队排行榜。
- 自动检测工作内容、虚拟机内部遥测、向 Guest 注入代码或在 Guest 内部署代理。
- 自定义音频、系统通知渠道及复杂的主题/插件系统。MVP 提案包含完成视觉提示与可选的内置短提示音（默认关闭），具体声音由用户评审。
- 高级日历、任务管理、远程控制和自动化工作流。
- 安全桌面及独占全屏上的可见性承诺；这些场景单独评估，不列入普通置顶能力。

## 4. 计时与恢复规则提案

### 4.1 轮次和阶段

- 提案默认：focus 25 分钟、short break 5 分钟、long break 15 分钟，每完成 4 轮 focus 后安排 long break。
- 用户启动阶段后，阶段标识、目标时长和开始时间构成该段记录。暂停期间不累计专注/休息时长。
- 进入 `completed` 后保留阶段完成结果；下一阶段由用户主动选择。产品不得因超时、唤醒或恢复检查自动补记未完成阶段。
- 用户提前结束或重置阶段时，记录实际活动时间和 interrupted 原因，不计入完成轮次。跳过休息同样记录 skipped，不自动启动专注。上述为统一统计口径提案。

### 4.2 时间变化、睡眠和锁屏

- 计时显示依据单调活动时钟的截止值与当前值之差更新，不依赖 UI 刷新次数累计。到期转换和历史记录以会话 ID 幂等写入。
- 系统休眠时暂停正在运行的阶段，并持久化休眠前状态；唤醒后显示恢复提示，询问用户继续计时或保持暂停。该行为是当前提案，须需求评审确认。
- 锁屏期间计时继续；解锁后按经过时间更新倒计时。
- 系统时钟变化时保持计时连续性与状态一致。实现需区分墙上时钟校正和机器休眠，并在架构评审中指定可测试策略。
- 应用异常终止或被强制结束后，重启进入 `recovery`，剩余时长取最近可靠快照，确认前停止推进。“继续计时”才进入running，“保持暂停”进入paused，“放弃本段”记录interrupted后进入idle。进程离线及睡眠期间的时长不从快照中扣除，不自动补完成。
- 恢复处理、保存失败或时间信息不可信时，界面明确说明状态并保留已有数据；禁止静默丢弃或伪造完成记录。

## 5. 窗口、托盘与 Hyper-V 边界

- 普通置顶目标覆盖 Windows 宿主机交互桌面上的常规应用窗口，包括宿主机管理 Hyper-V 虚拟机时的桌面场景。置顶层级、焦点抢占及多屏行为须通过验收案例确定。
- 本产品定义的 Hyper-V 可见性范围是宿主 Windows 桌面 overlay。普通置顶仅对宿主交互桌面中的普通窗口做目标承诺。
- Guest 虚拟机操作系统内部不提供窗口、托盘或计时注入。宿主上的 VMConnect 窗口及全屏模式分别实测宿主 overlay 的可见性；Guest 画面捕获与远程传输的内容范围由 Guest 桌面决定。
- Windows 安全桌面（例如 UAC 安全提示界面）与独占全屏应用独立列明边界和测试结果，不把普通置顶扩展解释为覆盖这些界面。
- 关闭窗口默认隐藏到托盘，计时继续。明确退出时，活动段先暂停，再选择“保存后退出”（留下paused恢复快照）、“放弃后退出”（interrupted）或“取消”（保留暂停）；保存成功后才结束进程。
- 若托盘不可用或初始化失败，主窗口保持可见并提供可操作的关闭/退出入口；错误以可见提示呈现。

## 6. 数据、隐私与错误反馈

- 本地保存会话阶段、开始/结束时间、实际计时、暂停区间、完成/放弃状态、配置及必要的恢复信息。字段、保留期限和存储格式待架构审批。
- JSON 导出包含明确 schema 版本、导出时间、统计数据与配置；CSV 用于可读统计，列名、日期格式和时区口径保持稳定并写入导出说明。
- “清空历史”先展示影响摘要，用户确认后生成可读取备份再执行删除；取消不改变数据，备份失败则中止。配置和活动会话保留；有活动会话时提示此范围。
- “永久清除全部本地数据”单独二次确认，先要求结束活动会话；清除历史、配置、活动快照和应用管理的备份，不自动新建备份。用户自行导出的外部文件由用户管理。完整删除与备份保留分别展示。
- 读写、导入/导出、备份和恢复错误都应明确提示操作、原因和下一步；保留原数据，避免静默失败。
- MVP 默认无需网络连接，不采集或上传使用数据。未来任何联网能力作为独立提案审批。

## 7. 资源预算提案

以下数字是目标值，尚未测量或验收通过。测试构建限定为 Windows x64 release；运行数据和测试环境随结果报告。

| 指标 | 提案目标 | 统一测量口径 |
|---|---:|---|
| 工作集 | ≤ 60 MiB | 启动后空闲稳定 5 分钟，任务管理器进程工作集 |
| 空闲 CPU | ≤ 0.5% | 空闲稳定 5 分钟，随后采样 60 秒平均 |
| 运行 CPU | ≤ 1% | 正常运行阶段采样 60 秒平均，不含导出等短时操作 |
| 冷启动 | ≤ 1 秒 | 从启动请求到主窗口首次可交互显示，10 次测量并记录中位数与最大值 |
| 磁盘占用 | ≤ 30 MiB | 安装/应用文件与默认本地数据分别记录，预算总计及计算边界在基线建立时固定 |

参考机器须在开发前登记 Windows 版本与补丁、CPU/RAM、显示器分辨率与缩放、Hyper-V 状态、电源模式、release 构建标识及测量工具版本。参考环境与数据尚待架构审批后确定。
